# Rio GA readiness audit — 2026-09-16

**Verdict: NO-GO for general availability.** Audited clean `main` at `1efc99e`. Automated checks pass, but confirmed privacy, data-integrity, and packaging defects remain, and the product's own live acceptance gates lack evidence. No project source or configuration was changed.

Implementation handoff: [GA release plan](GA_RELEASE_PLAN.md). This document preserves the audit findings at the revision above; it is not a claim about later fixes.

## Confirmed release blockers

1. **P1 — Responses requests enable default server-side storage.** [OpenAIInsightAdapter.swift:643](../Rio/OpenAIInsightAdapter.swift#L643) sends meeting context and insight state without `store: false`. Standard foreground Responses requests therefore retain application state for at least 30 days unless account-level controls such as ZDR override this. That is inconsistent with the stated temporary pipeline/two-day history boundary. Set `store: false`, assert it in request tests, and accurately disclose provider retention: this flag alone does not disable abuse-monitoring retention or every provider-side cache. Source: [OpenAI data controls](https://developers.openai.com/api/docs/guides/your-data).

2. **P1 — Two-day expiry is not enforced while Rio stays open.** [MeetingHistoryStore.swift:229](../Rio/MeetingHistoryStore.swift#L229) prunes only on load or record; [RecentMeetingsView](../Rio/ApplicationShell.swift#L1709) does not refresh expiry on opening. Leave the menu-bar process running for more than 48 hours without recording another meeting: expired transcript and cards remain visible and on disk. Pruning write failures are also swallowed. Schedule pruning while running and on wake/access, surface failures, and test clock advancement. The documentation must also clarify that an ordinary file cannot expire itself while the app is closed; a hard at-rest two-day guarantee needs a corresponding design.

3. **P1 — Stop discards untranscribed audio but saves a complete transcript.** [SessionOrchestration.swift:548](../Rio/SessionOrchestration.swift#L548) snapshots before shutdown; [OpenAITranscriptionAdapter.swift:475](../Rio/OpenAITranscriptionAdapter.swift#L475) cancels the collector and queued/in-flight transcription. Stopping 29 seconds into the default 30-second batch can save an empty transcript with `incompleteTranscript == false`; longer sessions lose the current batch and any backlog. Pause has the same discard behavior. Either drain under a documented bound or explicitly mark the saved prefix incomplete. Add stop/pause tests with partial and in-flight batches; existing stop tests inject already-finalized text.

4. **P1 — Quit bypasses meeting save.** [ApplicationShell.swift:158](../Rio/ApplicationShell.swift#L158) calls `NSApp.terminate(nil)` directly, and [RioAppDelegate](../Rio/RioApp.swift#L5) has no termination cleanup hook. Quitting during a meeting loses all finalized transcript and insights held in memory because the history recorder is reached only through lifecycle cleanup. Route normal application termination through asynchronous stop/save before permitting exit, and test active-session quit.

5. **P1 — Failed history saves are reported as success.** [MeetingHistoryStore.swift:242](../Rio/MeetingHistoryStore.swift#L242) publishes the new record before a `try?` save. On disk-full or permission failure, the meeting appears in Recent Meetings, but vanishes after restart; cleanup has already reset the transcript collector. Propagate save failure to the user and preserve a bounded retryable in-memory snapshot. Test record failure as well as deletion failure.

6. **P1 — The distributed DMG fails explicit disk-image signature assessment.** [package-dmg.sh:29](../scripts/package-dmg.sh#L29) creates an unsigned DMG. [verify-release.sh:37](../scripts/verify-release.sh#L37) validates its notarization staple but assesses the source app, not the disk image. The downloaded v1.0.2 DMG returned `rejected` / `source=no usable signature` for `spctl --assess --type open --context context:primary-signature --verbose=4`. Its inner app was accepted as Notarized Developer ID, so this is specifically a missing outer-image signing/verification gate, not evidence that the app lacks notarization. Sign the DMG before notarization, assess the exact distributed DMG, and verify a quarantined fresh-machine install. See [Apple packaging guidance](https://developer.apple.com/documentation/xcode/packaging-mac-software-for-distribution).

## Additional actionable defects and risks

- **P2 — Owner validation does not establish assignment.** [CoreContracts.swift:782](../Rio/CoreContracts.swift#L782) accepts an owner when the name merely appears anywhere in the source. “Alex described the outage. Sam will run the migration” can accept Alex as migration owner. More importantly, arbitrary attribution inside displayed card text is not validated at all; clearing `explicitOwner` does not remove “Alex will run the migration” from `text`. The no-guessed-owner promise requires grounding tied to the action and adversarial evaluation of rendered text, not just metadata tests.
- **P2 — Aggregate meeting history has no count or byte cap.** [MeetingHistoryStore.swift:261](../Rio/MeetingHistoryStore.swift#L261) only filters by date and sorts. Per-meeting limits do not bound total memory/JSON growth under repeated start/stop sessions. Add an aggregate cap and test overflow; architecture explicitly promises a meeting-count bound.
- **P2 — Deleting a selected custom profile ignores the edited Default profile.** [CoreDomain.swift:317](../Rio/CoreDomain.swift#L317) assigns static `.fallback` rather than `defaultProfile`. Edit Default, select a custom profile, then delete it: the next session silently returns to original guidance, 30-second pace, and empty vocabulary. Assign the configured default and test this sequence.
- **P2 — Capture callback violates the nonblocking callback rule.** [SystemAudioCapture.swift:207](../Rio/SystemAudioCapture.swift#L207) takes `NSLock.withLock` and [line 122](../Rio/SystemAudioCapture.swift#L122) allocates Data copies before enqueueing. The bounded queue does not make preceding work nonblocking. Remove blocking synchronization and consider preallocated bounded storage; validate callback timing under pressure. No actual hardware dropout was reproduced in this audit.
- **P2 — Pause can consume an insight batch without producing its result.** [CoreContracts.swift:306](../Rio/CoreContracts.swift#L306) advances delivered sequence state when creating a batch, before model generation succeeds. [SessionOrchestration.swift:350](../Rio/SessionOrchestration.swift#L350) cancels generation on pause; resume cannot request that same pending slice. Preserve/acknowledge the batch only after successful application or explicitly requeue it. This is a lifecycle-path defect; pause is not currently exposed by a visible shell button.
- **Privacy hardening, not a reproduced leak:** [OpenAIInsightAdapter.swift:39](../Rio/OpenAIInsightAdapter.swift#L39) copies the shared URLSession configuration, including disk-capable URLCache. An ephemeral session with disabled caching would make the local memory-only guarantee independent of server cache headers. Current OpenAI responses were not proven to be cached.

## Missing GA evidence

- [ROADMAP.md:35](../docs/ROADMAP.md#L35) explicitly leaves live permission grant/denial, real meeting audio through transcription and visible cards, restart/interruption/model-unavailable/stop-during-stage paths, and the bounded-memory smoke unverified.
- [ROADMAP.md:138](../docs/ROADMAP.md#L138) leaves the one-hour hardware soak and live interruption checks outstanding. Validate route changes, sleep/wake, denied/revoked permission, offline/rejected-key behavior, all supported cadences, resource growth, and cleanup with synthetic audio on supported Macs.
- The [evaluation pack](../docs/evaluation/incident-copilot-mvp/README.md#L27) has six synthetic scenarios and a rubric, but no recorded live-model scores. Fixture validation is not model-quality validation. Run the specified repeated trials, measure latency/unsupported claims/owner invention, and resolve the open acceptance and consent-policy decisions.
- The latest inspected successful signed release was v1.0.2 at `6312b10`. Audited HEAD is three commits newer, including workflow changes. Produce and verify a signed/notarized candidate from the actual release commit; an unsigned compile and an older notarized app are not that evidence.
- Release verification inspects the archive app instead of mounting and inspecting the DMG payload. Add payload, architecture, version, entitlement, and clean-install checks. The workflow accepts any syntactically valid semver tag; enforce the documented `main` ancestry policy if that policy is intended to be mandatory.
- Actual VoiceOver/keyboard interaction and a clean-machine onboarding/install test were not performed.

The roadmap's claim that notarization still awaits credential configuration is stale: v1.0.1 and v1.0.2 were successfully published. Update it from actual release evidence while keeping hardware and quality gates open.
